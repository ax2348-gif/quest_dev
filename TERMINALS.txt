QUEST LOCAL TERMINALS — runtime 1.5.1
===================================

ON THE HEADSET

1. Open Quest developer runtime from the app library.
2. Press Open new terminal. It opens a separate, resizable Quest window.
3. Press + Terminal in any terminal, or Open new terminal again, for another
   independent shell. Each has its own current directory, environment and jobs.
4. Use Keyboard for the headset keyboard, or type with a hardware keyboard.
   The toolbar supplies Ctrl-C, Ctrl-D, Esc, Tab, arrows and Enter.
5. Adjust Opacity for a translucent or opaque background. A-/A+ change text size.
   Brightness adjusts text/UI intensity. Contrast strengthens muted text and
   borders. Neither changes the background opacity. Appearance settings persist
   and are loaded when a terminal window is opened.

The local shell has the same app identity, home, workspace and installed
commands as SSH. It works without a network connection.

    quest-native status
    quest-native restart
    quest-native stop
    quest-app list
    quest-app launch dev.quest.guestdemo

LIFETIME

The terminal's small x closes its window while retaining its shell.
Use Reopen Terminal N in the original runtime window to return to it.
New shell replaces only that terminal's shell. End session stops that shell
and closes its window. These actions ask for confirmation.

Sessions survive closing windows, but not runtime process termination, APK
updates, force-stop, or headset reboot. Files in $HOME persist. Background jobs
that deliberately detach may require their own shutdown command.

There is no application-imposed single-terminal limit. Quest controls how
many panels it can display simultaneously; each additional terminal also uses
memory. Each shell retains up to 512 KiB of output for reopening, and the
visible terminal keeps up to 5,000 scrollback lines.

IMPLEMENTATION

Each session has a real Android PTY and /system/bin/sh. A small native exec
helper creates the controlling terminal; the Android JVM does not fork itself.
The packaged xterm terminal frontend is offline, with external navigation and
network requests blocked. It has no local HTTP server or added TCP listener.
The local terminal does not elevate Android permissions.
